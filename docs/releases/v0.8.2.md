# SlideForge 0.8.2

Released 11 November 2026.

Stability fixes from the [11 November audit](../audits/stability-performance-2026-11-11/REPORT.md), and the large-deck stall it found.

## Fixes

- **The first key typed into a text box is never lost.** Focus and the caret are placed as you click, not a frame later. A word selected by double-click no longer replaces text typed in the meantime.
- **Undo or a command that replaces a box's text while you are editing it** closes the editor without writing the old text back. A layout change, for example, no longer leaves a new text box empty.
- **Recording a show with the countdown skipped** waits for the presentation to start before the first slide change. Before, the recording could stay on the first slide.

## Large decks

- **The first edit after opening a deck rebuilds one slide, not all of them.** Sizes measured just after drawing (a text box's height, a picture's proportions, a plugin's drawing) made every slide look changed. On a 200-slide deck with a chart, an HTML embed and an animated background on every slide, the slowest edit went from 577 ms to 31 ms.
- **Charts are drawn when their slide is first shown**, when the presenter view previews it, or when you edit the chart. That deck held 214 drawn charts and now holds 35; drawing it takes 476 ms instead of 649 ms.

## Validation

- `ruff` and the backend tests (197) pass.
- Browser suites against a server set up as in CI (accounts off): UI smoke 25 passed, phase 2 and animations pass, regressions 309 passed; the regression for typing into a box right after a redraw passed 10 of 10 reruns.
- Against the desktop app's server, each suite on a fresh database: all 344 regressions, the three landscape suites, start screen (12), open project tabs, Projects tab, render performance (new checks: one slide rebuilt on the first edit, charts drawn with their slide and in the presenter preview), show recorder (11), async lifecycle, molecule trajectories and animation completion pass.
- The performance soak (`npm run test:performance-soak`) passes: decks of 10 to 200 slides rebuild one slide on their first edit; 200 redraws of the 200-slide mixed deck left the heap unchanged (−1 MB) with no detached charts; 60 project-tab switches took 21 ms at the median.
- Three tests that failed throughout 0.8.1 pass: the show recorder's slide sound, a late project open, and the 700 px top bar in the full desktop run.

**Not tested:** the desktop app's own window, macOS and Windows, and engines other than Chromium (WebKit could not start on the test machine).

This Git release does not imply a PyPI upload.
