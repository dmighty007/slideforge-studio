# SlideForge 0.8.3

Released 17 November 2026.

Fixes for the ways saving could lose work when a project is open in two windows, for a PowerPoint import that one slide could end, and for a Linux window that failed to start without a word.

## Saving

- **Ctrl+S after "Changed in another window" keeps the deck it replaces.** The server stores the other window's version as a revision before yours takes its place. Before, it was gone.
- **Unsaved edits that cannot be applied are offered back.** When a project was saved from elsewhere after your last unsaved edits, reopening it dropped them while the hint said "All changes saved". A notice now says so and stays until you choose "Restore my edits" or close it; restoring keeps the server's version as a revision too, and Ctrl+Z goes back to it.
- **Each project keeps its own unsaved backup.** With two projects open in two tabs, each tab's backup replaced the other's.

## PowerPoint import

- **A slide that cannot be read is left out, not the whole deck.** One such slide ended the import: the slides already read were dropped and an empty project stayed behind. The other slides now come in and a notice names the ones left out.

## Desktop on Linux

- **A window that cannot start says why.** When Qt cannot connect to the desktop (no Wayland display, a missing `xcb` library) it ends the process, so nothing was shown. The Qt platform is now checked first, and a failure names what to try: `slideforge --browser`, unsetting `QT_QPA_PLATFORM`, or `QT_QPA_PLATFORM=xcb` with `libxcb-cursor0`. The [install guide](../install.md#need-help) has the same steps.

## Internals

- The autosave queue, conflict handling, backups and the save on closing moved from `state.js` to `frontend/js/core/persistence.js`.

## Known limits

- Kept revisions have no restore screen yet; they are reachable through the Django admin.
- A link to a slide that was left out of an import points nowhere.
- Closing a browser tab while a new project's first save is still being created can lose that first edit.
- Importing within about a second of opening a project that has unsaved changes can fail with "sign in to import a presentation".

## Validation

- `ruff` and the backend tests (198) pass; the desktop tests (69, four of them new for the Qt platform check) pass.
- Against the desktop app's server, each of eight shards on a fresh database: all 347 regressions passed after the saving changes. After the import change, the 20 regressions that import PowerPoint files and the new one passed; the full suite was not rerun.

**Not tested:** the desktop app's own window, macOS and Windows, engines other than Chromium, and the other browser suites (UI smoke, recorder, landscape, performance).

This Git release does not imply a PyPI upload.
