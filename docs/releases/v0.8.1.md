# SlideForge 0.8.1

Released 11 November 2026.

A performance release. Times below were measured in headless Chromium, on a 47-slide deck imported from PowerPoint (576 objects) unless stated otherwise.

## Editing

- **Only the slides that changed are redrawn.** An edit used to rebuild every slide of the deck. Moving a box now takes about 28 ms instead of about 90 ms, and undo about 31 ms instead of about 135 ms.
- **Embedded content loads with its slide.** HTML and molecule embeds load when their slide is first shown, thumbnails are built as they scroll into view, and charts on slide thumbnails no longer animate. Opening a 40-slide deck builds 10 thumbnails instead of 40 and keeps 3 embedded documents running instead of 45.
- **Going back a slide no longer restarts an embed.** The embeds of the last three slides shown stay running; older ones are unloaded.
- **The chart panel** redraws the chart without its one-second grow-in animation after every edit in the data grid.

## Memory and saving

- **Undo history shares what did not change.** Each step was a full copy of the deck; 30 steps of the test deck held 32 MB and now hold 1 MB.
- **Saving checks only what changed.** Every autosave, unsaved-changes check and backup used to re-clean every object in the deck. The check now takes about 5 ms instead of about 21 ms, and an autosave about 77 ms instead of about 161 ms (server time included).

## Landscape Explorer

- **The 3D surface turns on the GPU.** Each frame of an orbit used to rebuild the whole surface on the CPU: 245 ms a frame for 81 × 81 samples, 450 ms for the three Wigner surfaces. The camera is now applied in the GPU's vertex shader, at about 6 ms of main-thread work a frame.
- Opening the explorer takes about 50 ms instead of 320–510 ms, and the pause after letting go of a drag about 100 ms instead of 600–1000 ms.
- Pictures match the previous renderer: across three test views, at most 8 pixels differ, none by more than 40 colour levels. Saved SVGs and the no-WebGL fallback keep drawing every face.

## Fixes

- The presenter view's preview of the next slide shows its HTML and molecule embeds, and slide thumbnails show molecule pictures, for slides not opened yet.
- Embeds load on the slide being shown even when the window does not have focus (presenting with the presenter view open).
- A text box whose content the sanitiser changed (a script in pasted HTML, for example) no longer keeps text built from what was removed.

## Validation

- `ruff` and the backend tests pass.
- Browser suites against a server set up as in CI (accounts off), on the editing, saving and embed changes: UI smoke 25 passed, phase 2 and animations pass, regressions 309 passed. A typing test that briefly lost the first letters typed into a box passed 10 of 10 reruns after its fix.
- Against the desktop app's server: the render-performance test (kept slides, shared undo, normalisation, chart panel, embeds), the three landscape suites, the start screen (12), open project tabs and the Projects tab pass.
- The landscape change was tested with the landscape suites and the render test; the other browser suites were run on the commit before it.

**Known failures, also present before this release:** the show recorder's "a slide's own sound is recorded when the browser shares no tab audio" and the async test "a late project open cannot replace the most recent choice" fail on 0.8.0 too. The 700 px top-bar layout test fails only inside the full desktop regression run and passes on its own.

**Not tested:** the GPU times on real graphics hardware (headless Chromium draws WebGL in software), macOS and Windows.

This Git release does not imply a PyPI upload.
